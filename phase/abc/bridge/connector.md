## 0. Abstract

This specification defines the egress architecture of the Fiber ecosystem, centering on the `worker.connector` and the three canonical workload archetypes (`deploy`, `finlib`, `oracle`). It establishes the structural methodologies by which isolated, legacy Web2 systems are integrated into deterministic, monetizable nodes within the Agent-to-Agent (A2A) economy—achieving this with **zero code modifications** to the underlying business logic.

## 1. The Edge Connector (`worker.connector`): The Physical-Logical Boundary

The `worker.connector` serves as a highly concurrent lock-free intermediary, resolving the impedance mismatch between the asynchronous intent mesh (DPHI Core) and synchronous physical legacy processes.

### 1.1. Zero-Trust Network Integration

* **Outbound Pull (NAT Traversal):** The connector operates without requiring inbound firewall exceptions by establishing outbound tunnels toward the DPHI Bus (`TunnelFactory`). This guarantees a zero-friction security posture, reducing network compliance overhead for infrastructure operators to absolute zero.
* **I/O Abstraction (Process Isolation):** Legacy applications require no proprietary SDKs or networking libraries. The connector spawns isolated subprocesses and communicates exclusively via **standard I/O (`stdin`/`stdout`)**, enforcing strict physical isolation between network logic and business execution.

### 1.2. Dual-Track Execution Topologies

1. **Ephemeral Mode (Fault-Isolated Sandbox):** Instantiates a discrete subprocess per incoming intent, terminating it upon resolution. This guarantees a mathematically pure, single-use sandbox, fundamentally eradicating memory leaks and state poisoning.
2. **Daemon Mode (State-Resident Multiplexing):** Designed for heavy-compute workloads requiring high initialization overhead (Init Tax). A single persistent process handles high-throughput multiplexing via Future-mapping, achieving O(1) lock-free concurrency.

### 1.3. Bidirectional Intent Mesh

* **SUSPEND & YIELD (State Parking):** When a legacy process demands asynchronous human intervention (`elicitation`), the connector intercepts this via stdout, parks the process in memory (suspending execution without terminating the process), and seals a `YIELD` state to the Core Ledger.
* **RPC Delegation (Callback Interception):** Enables sandboxed agents to query the Core Ledger or other peer nodes dynamically. The connector intercepts `rpc_delegate` payloads, executes the core RPC on behalf of the isolated agent, and re-injects the resolved data into the process's `stdin`.

## 2. Canonical Workload Archetypes

Any complex legacy system converges into one of three topological archetypes. The egress connector is designed to integrate these archetypes seamlessly into the A2A mesh.

### Archetype Alpha: Stateful Control & Human-in-the-Loop (`agent.deploy`)

**Objective:** Mitigate operational risk associated with destructive infrastructure manipulation by autonomous agents.

* **Topology:** Ephemeral Mode + Stateful Transaction
* **Mechanism:** Upon receiving destructive instructions (e.g., `DROP`/`TRUNCATE` in a production database), the legacy script halts and emits an `elicitation` payload demanding a 6-digit TOTP from an authorized human administrator.
* **Architectural Value:** Transforms legacy CLI scripts into **Finite State Machines (FSM) pending human consensus**, requiring zero asynchronous code rewrites. Infrastructure operators retain absolute infrastructural sovereignty while safely deploying autonomous agents into production environments.

### Archetype Beta: Stateless Deterministic Compute Daemon (`agent.finlib`)

**Objective:** Bypass the physical constraints of WASM sandboxes (e.g., inability to utilize C-Bindings) and minimize computational resource waste.

* **Topology:** Daemon Mode + Stateless Pure Compute
* **Mechanism:** Pre-loads computationally heavy C++ financial engines (e.g., TA-Lib, QuantLib) into memory, neutralizing initialization overhead. By supporting multi-dimensional matrix operations and strict AST whitelist validation, it minimizes IPC latency to near-zero.
* **Architectural Value:** Instigates **Compute Resource Optimization** within the A2A ecosystem. Agents forgo allocating local Fuel for heavy calculations and floating-point variances; instead, they route micro-payments (L402) to this node to query **"deterministically agreed-upon mathematical truth."**

### Archetype Gamma: Consensus Defense & Cryptographic Attestation (`agent.oracle`)

**Objective:** Shield external APIs from thundering herd conditions generated by high-frequency Agent Swarms.

* **Topology:** Daemon Mode + Local Consensus Caching (1.0s TTL)
* **Mechanism:** Wraps core modules that fetch and cryptographically seal data from external endpoints (e.g., Binance). Utilizing a `_cache_ttl = 1.0`, it serves hundreds of simultaneous intent queries from local memory.
* **Architectural Value:** Acts as a robust mitigation strategy against extreme concurrency. It resolves network I/O bottlenecks and API rate limit constraints, allowing a single external fetch to provide Ed25519-signed **Cryptographic Attestations** to an entire swarm of agents.

## 3. Synthesis & Systemic Convergence

The `worker.connector` and the three workload archetypes provide a standardized framework designed to federate centralized legacy infrastructure into the A2A network. This architecture enforces self-sustaining economic and structural efficiencies:

1. **Developmental Interoperability:** Mapping existing legacy codebases into these three archetypes establishes immediate interoperability with the A2A economy without requiring underlying logic modifications.
2. **Security & Compliance:** By processing NAT traversal, fault isolation, and DPoP/L402 validation entirely at the edge node, inbound network exposure and internal compliance friction for infrastructure operators are eliminated.
3. **Economic Determinism:** Through the removal of initialization overhead (Init Tax) and the enforcement of lock-free O(1) concurrency, the marginal cost of compute node operation approaches absolute zero, structurally optimizing routing efficiency across the protocol.
